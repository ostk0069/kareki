開発者や解析警告を調査する人に向けて、実装上の判定条件と制約をまとめます。利用者向けの概要は[解析の仕組み](how-it-works.ja.md)を参照してください。

## ライブラリ API

ランナー API は非同期です。呼び出し元を `async` にし、結果を `await` します。

```dart
final result = await KarekiRunner().run(request);
// analyze(request) も非同期です。
```

`DoctorRunner.run`、`DoctorRunner.analyze`、`runCli`、`runDoctor` も Future を返します。リクエストの作成と結果の表示は[実行可能なサンプル](https://github.com/ostk0069/kareki/blob/main/example/example.dart)を参照してください。

プレビュー時の `runCliAsync` / `runDoctorAsync`、`AnalysisMode` とそれを受け取る引数、`ParsedFile`・`DeclarationRecord`・`EntryPointSet` の旧方式の名前参照メタデータは削除されています。これらは API の変更であり、`dart run kareki` のコマンドは変わりません。

## 宣言の識別と参照グラフ

`AnalysisContextCollection` で参照先を解決し、宣言元ライブラリ・実ファイル・ 宣言位置・種別をキーに参照グラフを作ります。この内部 ID はベースラインの ID とは別です。起点ファイル、生成コード、アノテーションも宣言単位で扱いますが、明示的な `entry_points.names` は名前で照合します。実ファイルは一度だけ収集し、入れ子のパッケージでは最も内側のパッケージに所属させます。

静的に確定した Record のフィールドや、関数型に組み込まれた `.call()` は、無関係な同名メンバーと区別します。null アサーション（`!`）は元の宣言の読み取りとして扱います。import / export の show・hide は参照を維持しますが、関数値の受け渡しとはみなしません。コールバックや動的な呼び出しには、引き続き使用の可能性を考慮した判定を行います。

具体的な型引数を適用したメンバーや、フィールドの暗黙のアクセサは、元の宣言に対応付けます。メンバーから所属する型へ、コンストラクタから暗黙の親コンストラクタやリダイレクト先へも参照を補います。到達可能な型の継承実装と `call` / `toJson` は使用の可能性があるものとして残します。

未解決の参照は、参照元に到達できる場合に同名候補を残し、警告を出します。条件付き import / export の参照先も、プラットフォームをまたいで残します。動的ディスパッチやリフレクションを完全に追跡する解析ではありません。

## 条件付き import / export

次の条件を満たす場合に限り、分岐先を一律に起点とする扱いを、各分岐の宣言への参照に置き換えます。

- 全分岐が解決済みの、テスト用ではないライブラリである。
- 公開 API が同じ引数なし関数・getter で構成され、戻り値の型が明示されている。
- 戻り値の型が、表示名ではなく宣言 ID と null 許容性で一致する。

独自条件を含む全分岐を結び付け、実行環境の条件値は仮定しません。型・変数の宣言、export / part、入れ子の条件付き import、非公開ヘルパーを含む引数付きの宣言がある場合は対象外です。公開 API の戻り値が推論型・ジェネリック型・ワークスペース内の型である場合や、参照先の欠落・API の不一致がある場合も、従来どおり起点として残します。参照の解決に失敗した場合は解析を中止します。

この確認は参照先の置き換えに限られます。各プラットフォームの SDK や実行時の互換性を保証するものではありません。

## デコードした値

対応する JSON・YAML デコーダーの結果が、限定された読み取り専用の使い方を満たす場合は、無関係なワークスペース内の `[]` 演算子を使用中とみなす必要がなくなります。デコーダーの宣言と、結果のすべての使い方を確認します。未対応の経路では、使用の可能性がある宣言を引き続き残します。条件の詳細、ソースの照合方法、更新手順は[デコーダーモデル](decoder-models.ja.md)を参照してください。

## 省略可能な引数

未到達のコードや生成コードを含む全呼び出しを、宣言 ID ごとに集計します。実際のオーバーライドとリダイレクトファクトリの関係に沿って結果を伝え、無関係な同名宣言とは混ぜません。super 仮引数から親に渡る値は、子の呼び出しで省略されたときのデフォルト値も含めて集計します。

tear-off（関数を値として取り出す操作）、暗黙の呼び出し可能型への変換、動的な呼び出し、未選択の条件付き参照先では、正確な使用状況が分からなければ未使用とは判定しません。コールバックの解析は以下の範囲に限り、一般的な関数間データフロー解析は行いません。

各引数には `used`・`unused`・`unknown` の状態があります。既知の呼び出しで使用が確認できれば、ほかに不明な経路があっても `used` です。 `unused` は、調べた呼び出しで指定がなく、不明な経路も残らないという **解析範囲内の判定**です。外部 API の未使用や、削除の安全性までは保証しません。指摘には引数単位の `unused` 判定が必要で、既存の抑制や生成ファイルの除外も適用します。

全引数の使用が確認できたコールバックには、ほかに不明な呼び出し経路があっても引数の解析警告を出しません。未確認の引数と不明な経路が残る場合は、警告を維持します。

### 直接呼び出すコールバック

関数値を引数全体として渡し、受け取り先がトップレベル関数・static メソッド・ extension メソッドに確定する場合、その同期的な本体を調べます。受け取る仮引数の全参照が `callback(...)` または組み込みの `callback.call(...)` による直接呼び出しであるか、参照自体がない場合に限り、位置引数の数と名前付き引数を集計します。

呼び出し結果の return や、同期ジェネレーター（`sync*`）での yield は扱えます。ただし、関数値そのものの保存・yield・return・転送・別名への代入・キャスト・ 再代入・クロージャへの取り込みがあれば、この判定は使いません。

対象となる非 SDK 依存の本体は、元の解析セッションで part を含めて解決します。本体が取得できない場合や解決エラーがある場合は、未使用とは判定しません。依存先の本体を指摘対象や解析の起点に加えることもありません。 async、`BuiltList.map` を含む仮想メソッド、関数変数を介した受け取り先、 SDK の本体は対象外です。

全ファイルの走査後に集計結果を適用し、その後でオーバーライドとリダイレクト先に反映します。ライブラリ名や、引数を制限したコールバックの型だけでは安全性を判断しません。

### 保存されるコールバック

対象となる外部コンストラクタでは、値を変更しないコンストラクタ間の受け渡し、リダイレクトファクトリ、final な関数フィールドをたどり、実際のフィールド呼び出し式から、指定された引数を集計します。これは使用の可能性を追加する処理であり、**未使用の証明には使いません**。

フィールドは宣言単位で区別しますが、インスタンスごとには区別しません。特定のオブジェクトや実行時の分岐で呼び出されることを証明するものではありません。保存されたコールバックについて、観測できた呼び出しだけで全経路を把握したとは判断せず、使用の根拠がない引数は `unknown` のままにします。

コンストラクタ仮引数の未対応の使い方や再代入があれば、その値の転送を採用しません。変更可能なフィールド、明示的な getter、任意の別名・キャスト、別パッケージへの転送は対象外です。元の解析セッションで、同じ依存パッケージの import / export 先を 128 ライブラリまで調べます。ワークスペースのソース、解決エラー、上限超過が含まれる場合は、そのグループの使用根拠を採用しません。

## 警告の根拠を読む

警告には調査の手掛かりを載せますが、偽陽性かどうかを自動判定するものではありません。

| 警告の対象 | 表示する根拠 |
|---|---|
| 引数 | 未確認の引数名、既知の位置引数の数・名前付き引数、関数値の受け渡しなど不確実性の発生位置。 |
| 仮想メソッドに直接渡すコールバック | 静的に解決した受け取り先、レシーバーの型、取得できるフィールド・getter・ローカル変数の参照先（末端から根元の順）。 |
| 未解決の参照 | 全発生位置、取得できるレシーバーの静的型、使用の可能性がある宣言の候補。 |
| 条件付き参照 | import / export の指定、条件、ワークスペース内の参照先。 |

保存されたコールバックの警告では、フィールド経由で呼び出される可能性の根拠を、未確認の経路と区別して示します。オーバーライドやリダイレクト先に結果を伝える場合も、元の理由を残します。

これらは静的な情報であり、**実行時の値の生成元や呼び出し先を確定するものではありません**。 final フィールド、公開ファクトリ、`copyWith`、キャストだけでは、値が実行時にどこで生成されたかは確定できません。警告に表示した情報だけを根拠に、使用の可能性があるコードを未使用へ変更することはありません。

呼び出し引数や入力データのリテラルは転載しませんが、条件付き import / export の URI と比較条件は表示します。未使用と判断する前に、固定されたバージョンの依存ライブラリも含めて、値の受け渡し先を確認してください。人手で確認しただけでは警告は解除されず、指摘や doctor の検査可否も変わりません。

出力先と終了コードは [CLI リファレンス](cli.ja.md)と [doctor](doctor.ja.md)を参照してください。

## 1 回の解析内での再利用

doctor は、使用状況に依存する検査で 1 回の解析結果を共有します。参照グラフの構築には宣言と参照の索引を使います。同じ解析コンテキストでは、解決済みのライブラリを part 間で再利用し、テスト用ソースの分類と継承メソッドの検索結果も実行内でキャッシュします。

実行間で残る解析キャッシュはありません。これらの最適化によって、ソースの収集範囲や上記の判定条件を変更することはありません。

性能を比較する場合は、`dart tool/resolved_analysis/benchmark.dart ROOT [doctor]` を使い、SDK・ソース・設定・ルールを揃えてください。毎回新しいプロセスで複数回測定し、所要時間とメモリ使用量のピーク（RSS）を確認します。ソースの変更による差と解析方式による差は分けて測定してください。
