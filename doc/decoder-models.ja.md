デコード結果を読み取り専用のデータとして扱い、無関係なワークスペース内の `[]` 演算子を使用中とみなさずに済む条件を、開発者向けに説明します。入力の形や実行時の成功を保証する検査ではありません。

## SDK の JSON デコード

reviver を省略した `dart:convert` の `jsonDecode(source)` と、標準の `json.decode(source)` が対象です。`decode` という名前や `JsonCodec` 型だけでは判断せず、解決した宣言と標準 SDK のレシーバーを確認します。

読み取り専用の入れ子の添字アクセス、対応する組み込み型へのキャスト、 final なローカル変数への別名の代入を追跡し、同じソースファイル内の全参照を調べます。不変なスカラー型へのキャストや、組み込み Map の keys 参照で終わる経路、または未参照の final ローカル変数に限定します。

保存、return、引数への受け渡し、クロージャへの取り込み、変更、未対応の操作があれば、同じデコード結果に由来する値全体を対象外にします。読み取りより後の操作であっても同じです。条件を満たす場合も、レシーバーと添字の式に含まれる参照は通常どおり収集します。

独自のコーデック、コーデックの別名、明示的な reviver（null を含む）、変更可能なローカル変数は対象外です。

## ソースを照合する外部デコーダー

外部モデルは依存パッケージだけに適用し、収集したワークスペース内のソースには適用しません。パッケージ名やメソッド名からの推測ではなく、レビュー済みの実装について確認した性質を使います。

| モデル | レビュー済みバージョン | 対象の呼び出し |
|---|---|---|
| JSONC | jsonc 0.0.3 | `jsoncDecode`、標準の `jsonc.decode`（`JsoncCodec.decode`）。 |
| YAML | yaml 3.1.3・3.1.4 とレビュー済み依存先 | `loadYaml`。 |

`external_decoder_models.dart` のカタログでは、解決した非 SDK の import / export / part を推移的にすべてたどり、SHA-256 を照合します。各ソースのライブラリ URI、ソース URI、実効言語バージョン、内容のハッシュを含めます。インストール先の絶対パスは、同じ実装であることの根拠にはしません。

ソースの変更・欠落・曖昧さ・読み取り失敗・未レビューの実装があれば、モデルを無効にします。バージョン番号だけでは有効になりません。照合結果のキャッシュは 1 回の解析内に限ります。未対応のバージョンも解析できますが、使用の可能性がある宣言を残すため、レビューが済むまで警告が出る場合があります。

## 読み取り専用の反復処理と YAML のコンテナ

モデル由来の組み込み List を使う、同期的な `for (final item in list)` 文にも同じ読み取り条件を適用します。final な別名や入れ子の読み取りにも対応します。変更可能な反復変数、独自の Iterable、collection-for、await-for、クロージャへの取り込み、変更、追跡範囲外への受け渡しは対象外です。

YAML モデルでは、YamlMap / YamlList へのキャストと YamlMap の keys も扱います。 YAML のキーはコンテナの場合もありますが、レビューしたローダーが生成するコンテナは読み取り専用です。null との比較も読み取りとして扱います。デコーダーのフック、明示的な名前付きオプション、任意のサブクラスは対象外です。モデルを適用しても、同じファイル内のほかの動的な呼び出しまで検査対象外にはしません。

## モデルを更新するときの確認

新しいハッシュを登録する前に、次の確認を行います。

1. デコーダーの定義と、推移的に参照する実装をレビューします。
2. デコード結果から、ワークスペース内の任意の演算子が呼ばれないことを確認します。
3. `tool/resolved_analysis/decoder_model_snapshot.dart SOURCE_FILE LIBRARY_URI` で参照先を確認します。ハッシュを取得しただけでは承認になりません。
4. `test/runner/resolved_decoders_test.dart` に正常系と反例を追加します。ソースの変更、配置先の変更、同名の別実装、値の変更、追跡範囲外への受け渡し、ワークスペースに取り込んだ実装を含めます。
5. レビューとテストが完了してからカタログを更新します。

解析全体については[解析の内部仕様](analysis-internals.ja.md)を参照してください。
