宣言単位の解析方式だけを使用します。

1. `melos.yaml` または pub workspace 経由でパッケージを検出する。
2. `package:analyzer` で全 `.dart` ファイルをパースし、宣言のメタデータと抑制指示を抽出する。
3. エントリポイントを解決する（暗黙の規約、有効なプリセット、生成ファイル中の参照、設定の組み合わせ）。
4. analyzerで参照先を解決し、宣言IDのグラフをエントリポイントから辿る。
5. 到達できなかった宣言、参照されていないファイル、宣言されていない pub 依存を報告する。

## Entry-point seeding

エントリポイントは 4 つのレイヤから種出しされます。

| レイヤ | 出どころ |
|---|---|
| 暗黙 | Dart / Flutter SDK の規約（`main`、`_test`、`bin/`、`integration_test/`、`lib/l10n/`、`flutter_test_config.dart`）。 |
| ツール規約 | `entry_points.files` 設定（デフォルト: playbook / widgetbook 用の glob）。 |
| アノテーション | 有効なプリセットの keep-alive、`custom_presets.*.keep_alive_annotations`、`keep_alive_annotations.custom`。 |
| 生成コード | `exclude.files` にマッチするか `GENERATED CODE` ヘッダを持つファイル — それらの識別子参照が BFS のルートとして使われます。 |

このレイヤ構造により、コード生成を多用するエコシステムでも false positive を撒き散らさずに kareki を共存させられます。

## 宣言単位の解析

宣言単位の解析方式は `AnalysisContextCollection` で参照先を解決し、
ライブラリ・実ファイル・宣言位置・種別に基づくIDでグラフを作ります。
この内部IDはベースライン用のIDとは別です。起点ファイル・生成コード・
アノテーションからの起点も宣言単位になります。
明示的な `entry_points.names` は従来どおり名前一致の指定として扱います。
ネストした workspace package は最内側を所有者として実ファイルを一度だけ収集します。
静的に確定した Record のフィールド参照は、無関係な同名宣言への参照とみなしません。
関数型の組込み `.call()` も同様に区別し、`!` は更新式ではなく元の宣言の読み取りとして
扱います。import/export の show・hide は参照を維持しますが、関数値の受け渡しとは
みなしません。実際の callback や dynamic な呼び出しへの保護は維持します。

ジェネリクスの具体化やフィールドの暗黙accessorは元の宣言に対応付けます。
メンバーから所属する型へ、コンストラクタから暗黙のsuper・redirect先へも
参照を補います。到達可能な型の継承メンバーや `call` / `toJson` は保守的に保護します。
未解決参照は呼び出し元が到達可能な場合に同名候補を保護し、警告を出します。
条件付きimport/export先もプラットフォームをまたいで保守的に保護します。
動的ディスパッチやreflectionを完全に追跡する方式ではありません。

限定された条件付き参照では、一律の root 保護を全候補への参照に置き換えます。
全分岐が解決済みの非テストライブラリで、公開 API が同じ引数なし関数・getter のみ、
戻り値が明示されている場合に限ります。型は表示名ではなく宣言 ID と nullability で
照合します。独自条件を含む全候補を結び付けるため、環境変数の値は推測しません。
型・変数の宣言、export / part、入れ子の条件付き import、private helper を含む引数、
公開 API の推論型・generic 型・workspace 型の戻り値、欠けた参照先や API の不一致がある場合は
従来の保護を維持します。解決エラーでは解析全体を中止します。
これは局所的な参照先の置換に関する確認で、各プラットフォームの SDK・実行互換性の証明ではありません。

限定的な値の出所の追跡として、reviver を省略した `dart:convert` の
`jsonDecode(source)` と標準の `json.decode(source)` に対応します。
読み取り専用の入れ子の添字アクセス、対応する組込み型への cast、final なローカルの
別名を追跡し、単位ファイル内の全参照を検査します。不変なスカラー型への cast や
組込み Map の keys 参照で終わる経路、未参照の final ローカルに限定します。
保存・return・引数への受け渡し・capture・変更・未対応の操作があれば、読み取りより後の
操作であっても、そのデコードに由来する値全体の証明を取り消します。
証明できた読み取りでは workspace の無関係な `[]` を保持せず、receiver や添字の
式そのものの参照は従来どおり収集します。入力の形や実行時の成功を保証するものではありません。
独自 codec・codec の別名・明示的な reviver（null を含む）・変更可能なローカル・
未対応の操作は対象外です。`decode` という名前や `JsonCodec` 型だけで判断せず、
解決した宣言と標準 SDK の receiver を確認します。

外部 decoder は、任意の本体を自動証明するのではなく、**監査済みソースの解析モデル**を
使います。`jsoncDecode` / 標準の `jsonc.decode` と `loadYaml` は、宣言元と
推移的な非 SDK の import / export / part 全体、実効言語バージョンを含む SHA-256 が
監査済みの値と一致する場合だけ対象にします。対象は jsonc 0.0.3、yaml 3.1.3 / 3.1.4
と監査済み依存先の組合せです。名前・バージョンだけでは有効にせず、変更・欠落・曖昧な
参照・未監査の実装では保守的な保持に戻します。承認キャッシュは解析 1 回に限定し、
workspace 内で解析対象になっている decoder の宣言を外部扱いして除外しません。

同じ読み取り限定の検査で、モデル由来の組込み List を使う同期的な
`for (final item in list)` 文も追跡します。変更可能な反復変数・独自 Iterable・
collection-for・await-for・capture・変更・外部への受け渡しは対象外です。
YAML では YamlMap / YamlList への cast と YamlMap の keys を許可します。
YAML のキーはコンテナの場合もありますが、監査した loader の結果のコンテナは読み取り専用です。
null との比較も読み取りとして扱います。decoder の hook と明示的な名前付きオプションは
対象外です。入力の妥当性や、ファイル内のすべての dynamic 呼出の安全性を保証しません。
依存更新時は `tool/resolved_analysis/decoder_model_snapshot.dart SOURCE_FILE LIBRARY_URI`
で参照先を確認し、実装の監査・回帰テスト後にカタログを更新します。
このツール自体が新しいハッシュを自動承認することはありません。

プログラムからは `await KarekiRunner().analyze(request)` または
`await KarekiRunner().run(request)` を使います。[移行手順](migration.ja.md)も参照してください。

optional引数は同じ宣言IDをキーとして、未到達・生成コードも含む全呼び出し箇所から
集計します。実際のoverride関係とredirecting factoryを通じて使用状況を伝播させ、
無関係な同名宣言とは混ぜません。tear-off・暗黙callable変換・dynamic・
未選択の条件付き参照先は、正確な使用状況が分からない場合に保守的に保護します。
callbackの解析は下記の直接利用に限定し、一般的な関数間データフロー解析は行いません。
super仮引数は解決済みの親引数へ転送される値（省略時のデフォルト値も含む）として
集計します。また、別の既知の呼び出しで全任意引数の使用が確認できる場合には、
callback経由の呼出が残っていても「任意引数が未使用か」の警告は出しません。
未知の呼出経路があり、未確認の任意引数が残るcallbackは引き続き保護します。

各任意引数を `used`（使用確認済み）、`unused`（解析範囲内で未指定）、
`unknown`（不明）に分けます。未知の経路があっても、別の経路で使用を確認できれば
その引数は `used` です。`unused` は調べた呼出に指定がなく、未知の経路も残らない
という解析範囲内の判定であり、外部API利用の不存在や削除の安全性までは保証しません。
指摘には引数単位の `unused` 判定を要求し、既存の抑制・生成ファイル除外も維持します。

関数値を引数として直接渡し、受け取り先がトップレベル関数・static・
extensionメソッドに確定する場合、その同期的な本体を調べます。
同じ仮引数の全参照が `callback(...)` / 組込み `callback.call(...)` による直接呼出、
または参照自体がない場合に限り、渡す位置引数数・名前付き引数を集計します。
呼出結果のreturnや同期generator（`sync*`）のyieldは許可しますが、
関数値そのものの保存・yield・return・転送・別名化・cast・
再代入・クロージャへの取り込みがあれば確定しません。
選択された非SDK依存のconsumerも、元の解析sessionでpartを含めて本体を解決します。
本体が取得できない場合や解決エラーがある場合は保護を維持し、依存本体を
指摘やentry pointの対象には加えません。async、`BuiltList.map`を含む仮想呼出、
関数変数を介したconsumer、SDKの本体は対象外です。
全ファイルを走査してから結果を適用し、その後override / redirectへ伝播させます。
ライブラリ名や狭いcallback型だけを安全性の根拠にはしません。

保存されたcallbackには、使用の可能性だけを追加する別の解析を行います。
選択された外部コンストラクタの引数を、変更しないコンストラクタ間の受け渡し・
redirecting factory・finalな関数fieldへ追跡し、実際のfield呼出式から
渡された引数を集計します。**未使用の証明や、保存されたcallbackの保護解除には使いません**。
fieldは宣言単位で区別しますが、同じfieldのインスタンス同士は区別しません。
この使用証拠は保守的な潜在経路であり、特定のオブジェクトや実行時の分岐で
その呼出が実行されるという証明ではありません。
コンストラクタ仮引数の未対応の利用・再代入はその転送を無効にします。
変更可能なfield・明示的getter・任意の別名/cast・別パッケージへの転送は扱いません。
元の解析sessionで、同じ依存パッケージのimport/export先を128ライブラリまで調べます。
workspaceのソース・解決エラー・上限超過があれば、そのグループの使用証拠を採用しません。
警告には潜在的なfield経由の呼出位置を別途示し、使用証拠がない引数は
callback保存後も `unknown` のまま維持します。

警告にはレビュー用の根拠を表示します。偽陽性の自動判定ではありません。
引数警告には未確認の引数名・既知の引数数と名前・関数値などの不確実性の発生位置を
載せます。仮想メソッドへ直接渡すcallbackには、受け取り先の静的な宣言位置・
receiverの型・取得できるfield/getter/localの参照先を末端から根元の順に追加します。
これは静的な束縛であり、**実行時の値の生成元を証明するものではありません**。
final field・公開factory・`copyWith`・castだけでは生成元は閉じず、この診断情報で
保護を解除しません。override / redirectで伝播した場合も原因を保持します。未解決参照には
全発生位置・取得できるreceiverの静的型・保持候補の宣言を載せます。
候補は実行時の呼出先と確定したものではありません。条件付き参照には
directive・条件・workspace内の対象を表示します。呼出引数や入力データのリテラルは
転載しませんが、条件付きdirectiveのURI・比較条件は表示します。
未使用と判断する前に、固定された依存ライブラリも含めて値の受け渡し先を確認してください。
人手による判定だけでは警告を解除せず、指摘やdoctorの整理保留も変更しません。

## Supported versions

| コンポーネント | バージョン |
|---|---|
| Dart SDK | `>=3.10.0 <4.0.0` |
| analyzer | `>=10.2.0 <15.0.0` |

CI では、サポートするすべての Dart minor version と、最新 stable SDK の patch version に対して解析とテストを実行します。
