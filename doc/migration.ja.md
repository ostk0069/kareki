次のリリースでは、到達可能性と省略可能な引数を、analyzer が解決した宣言単位で解析します。従来の解析方式と切り替えオプションは削除されます。参照の解決に失敗しても、従来方式で解析をやり直すことはありません。

## CLI の移行手順

1. プロジェクトの SDK で依存パッケージを取得し、コード生成を実行します。生成ファイルや除外ファイルも参照の解析に使うため、正常に解決できる必要があります。 SDK と analyzer は、プロジェクトで使う言語機能に対応している必要があります。実験的な構文をパースできるだけでは不十分です。
2. 設定の `analysis_mode` とスクリプトの `--analysis-mode` を削除します。廃止されたオプションを指定すると終了コード `64` になります。
3. kareki を実行し、ベースラインを更新する前に指摘を確認します。ベースラインの ID と JSON 形式は変わりませんが、同名宣言を区別することで新しい指摘が出る場合があります。パッケージ指定は報告範囲だけを絞り、参照の収集は続けます。
4. 古い抑制設定を削除する前に `dart run kareki doctor` を実行します。終了コード `2` は、安全に検査を完了できなかったことを示します。問題なしという意味ではありません。

参照の解決に失敗した場合は、途中までの指摘を出力せず、ベースラインも上書きしません。一方、解析警告では使用の可能性があるコードを残し、通常の実行は失敗扱いにしません。 [CLI の終了コード](cli.ja.md)と [doctor](doctor.ja.md)を参照してください。

## ライブラリ API の移行

ランナーと CLI の API は `await` して呼び出します。

```dart
final result = await KarekiRunner().analyze(request);
// run(request) も非同期です。
```

- `KarekiRunner.run`、`KarekiRunner.analyze`、`DoctorRunner.run`、 `DoctorRunner.analyze` は Future を返します。
- `runCli` と `runDoctor` も Future を返します。プレビュー時の `runCliAsync` と `runDoctorAsync` は削除されます。
- `AnalysisMode` と、それを受け取る引数は削除されます。
- `ParsedFile`、`DeclarationRecord`、`EntryPointSet` の、従来方式で使っていた名前参照のメタデータは削除されます。

## パフォーマンスの比較

参照を解決する解析は、名前の照合より処理量が増えます。差を測る場合は、 `tool/resolved_analysis/benchmark.dart ROOT [doctor]` を使い、 SDK・ソース・設定・ルールを揃えて比較してください。毎回新しいプロセスで複数回実行し、所要時間とメモリ使用量のピーク（RSS）を確認します。ソースの変更による差と解析方式による差は分けて測定してください。

実行間で残る解析キャッシュはなく、実行ごとに現在のソースを読みます。参照の解決が不要なルールは、依存パッケージの準備なしでも実行できます。 1 回の実行内での再利用については[解析の内部仕様](analysis-internals.ja.md)を参照してください。
